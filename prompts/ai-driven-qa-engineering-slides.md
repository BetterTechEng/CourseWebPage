## Slide 02 — AI will build more software. Someone has to decide if it can be trusted.

*01 / Why now*

**SDLC — Software Development Lifecycle:** people plan, build and test in stages.

**ADLC — Agentic Development Lifecycle:** AI agents build, test and fix code in a continuous loop while people direct and review.

More generated code means more decisions about trust. **Quality is no longer a final checkpoint. It is what makes AI speed usable for the business.**

### Work moves through handoffs.

Quality feedback arrives late

| Step | Stage | Purpose |
| --- | --- | --- |
| 01 | **Requirements** | Define the scope |
| 02 | **Design** | Plan the solution |
| 03 | **Build** | Produce the change |
| 04 / QA gate | **Test** | Queue grows as AI speeds up build |
| 05 | **Release** | Wait for approval |

**The bottleneck:** faster code reaches the same downstream test queue. This is a simplified pattern; many SDLC teams already test earlier.

ADLC / Continuous quality

### Build, validate and improve together.

Quality stays in the loop

**Human direction and review** Business context · Architecture · Risk limits · Release approval

| Step | Stage | Purpose |
| --- | --- | --- |
| 01 | **Understand** | Requirements + risk |
| 02 | **Generate** | Code + test assets |
| 03 | **Validate** | Run checks + review evidence |
| 04 | **Improve** | Fix + update the context |

**Feedback loop:** Improve → Understand. Evidence feeds the next change.

AI agents support the continuous loop. Engineers set the direction, validate the evidence and approve the release.

**AI lets developers ship faster. If QA does not change too, testing becomes the bottleneck that erases those gains.**
